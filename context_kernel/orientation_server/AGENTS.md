The OrientationServer scope provides a read-through MCP (Model Context Protocol) interface over the materialized knowledge tree, acting as the primary query surface for agents and engineers exploring the codebase. Its core responsibility is to serve two MCP tools — `overview(scope, max_tokens)` and `find(query, scope, max_tokens)` — that let consumers retrieve structured summaries of any scope or perform embedding-similarity search across the hybrid corpus. The scope hides the backend choice (KnowledgeStore, Embedder) behind function parameters, making it testable and backend-agnostic.

The public API surface consists of the `serve` function in `__init__.py` and the tool implementations in `tools.py`. `serve(tree_root, store, config, embedder)` launches a FastMCP stdio server, wiring the tools into the MCP lifecycle. The `overview` tool reads from the materialized tree at `tree_root`, producing a markdown summary capped by `max_tokens` with source file citations. The `find` tool orchestrates a multi-stage pipeline: `nearest_chunks` embeds the query and retrieves top-k results from the hybrid corpus via the KnowledgeStore, `rank_by_relevance` reranks those hits using a scoring protocol that boosts results by 1-hop graph adjacency (per ADR-0015/0023), and `assemble` concatenates the final chunks with file-path citations while enforcing the token budget. The private `_expand_neighbors` function implements ADR-0023's expansion logic, pulling in graph neighbors of strong seeds when the vector search misses them.

Internally, the scope depends on `context_kernel.scoring` for `ScoringConfig` and relevance scoring, `context_kernel.graph.protocol` for the `KnowledgeStore` and `SearchResult` types, and `context_kernel.types.ScopePath` for scope identification. The `find` tool optionally accepts an `Embedder` for query embedding; when `None`, it falls back to the store's default. The `assemble` function uses a private `_CHARS_PER_TOKEN` constant for budget enforcement. This scope follows a layered pipeline pattern — search, rerank, expand, assemble — with each stage isolated into its own function for clarity and testability.
