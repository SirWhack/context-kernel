This scope defines the scoring and relevance system for the context kernel, responsible for computing trust signals that rank entities and relationships during search and summarization. The system answers the question "which claims should I trust and show first?" by combining three axes: authority (source credibility), centrality (structural importance), and drift (staleness measured via git churn). These scores are computed at ingest time, stored on entities and relationships, and consumed at query time by `tools.find` and `summarize_scope`.

The public API surface consists of scoring functions in `context_kernel/scoring.py`: `authority(sources, cfg)` returns the max authority over a node's source paths using a configurable mapping of source kinds (THEORY=1.0, ARCHITECTURE=0.95, ADR=0.9, CODE=0.85, etc.); `edge_weight(kind, cfg)` maps relationship kinds to weights (governed-by=0.95, implements/realizes=0.9, supersedes=0.85, etc.); `edge_drift(lines_changed, referent_size)` computes normalized churn as `min(1, lines/size)`; `centrality(node_sources, relationships, cfg)` computes distinct-source in-degree over backbone edge kinds, normalized to [0,1]; and `confidence(authority, node_drift)` combines them as `authority × (1 - node_drift)`. At query time, `find_score(similarity, confidence, proximity)` assembles relevance per ADR-0019, and `summarize_weight(confidence, centrality)` controls ranking order.

Internally, the system follows a layered architecture. The `change_detection` module handles all git I/O (cached per path) to compute drift, while `scoring` never touches the filesystem. Scoring configuration resolves via a precedence chain: hardcoded defaults → `[ingester.scoring]` config section → `CK_SCORING_*` environment variables. The system uses a "safe defaults" design principle (ADR-0019 §10): missing data never raises errors—no sources yields default authority, size 0 yields drift 0, unknown edge kinds yield mid weight. Schema fields are additive, so old `state.json` loads with neutral defaults (confidence=1.0, centrality=0.0, drift=0.0) until the next ingest.

Key design decisions include: separating structural edges (from syntax trees) from semantic edges (from LLM inference) by renaming `implements` to `realizes` to avoid conflation; isolating drift as the heaviest confidence axis in Slice 3 after the scaffold exists; making centrality scoring optional at query time (off by default); and ensuring relevance is assembled per `find` call from similarity, confidence, and proximity—never stored. The system depends on `graph/protocol.py` for Entity, Relationship, and SearchResult field definitions, and on `lightrag_adapter.py` for serialization round-trips.
