# S2 — Wire pre-commit git hook for documentation regeneration

**Status:** spec complete, ready to build.
**[PLAN.md](../../PLAN.md) reference:** §S2.
**Authors of this spec:** decisions from `/grill-with-docs` session on 2026-05-24.

## Goal

A checked-in `.githooks/pre-commit` script that runs `ck ingest && ck materialize --all` before every commit, stages the changed materialized files, and blocks the commit if regeneration fails. A `ck init` subcommand sets `core.hooksPath` to wire it up. This replaces the PreToolUse hook design from the original S2 — see [ADR-0010](../adr/0010-pre-commit-hook-regeneration.md).

## In scope

- `.githooks/pre-commit` hook script (checked into the repo)
- `ck init` subcommand (sets `git config core.hooksPath .githooks`)
- `ck materialize` change: print list of files written to stdout
- Staging of changed materialized files in the hook

## Concrete specs

### `.githooks/pre-commit` script

```bash
#!/usr/bin/env bash
set -euo pipefail

# Regenerate documentation from current source state
ck ingest --portfolio .
CHANGED_FILES=$(ck materialize --all)

# Stage any materialized files that changed
if [ -n "$CHANGED_FILES" ]; then
    echo "$CHANGED_FILES" | xargs git add
fi
```

**Rules:**
- Exits non-zero if `ck ingest` or `ck materialize` fails — commit is blocked.
- Developer can bypass with `git commit --no-verify` in an emergency (explicit, visible choice).
- `ck materialize --all` prints one file path per line to stdout for each file it wrote.
- Only files actually written by this materialization are staged — not a blanket `git add **/AGENTS.md`.

### `ck init` subcommand

```
ck init [--portfolio ROOT]
```

Runs `git config core.hooksPath .githooks` in the portfolio root. Idempotent. Prints confirmation message. Does not create `.githooks/` (that's checked in).

**Exit codes:**
- 0: success (hooksPath set)
- 1: not a git repository, or `.githooks/pre-commit` not found

### `ck materialize` output change

Currently `ck materialize` writes files silently. S2 adds: print one absolute path per line to stdout for each file written (both `AGENTS.md` and `CLAUDE.md` bridge files). Files whose content did not change are not printed (idempotent — only newly written or modified files appear).

This output is consumed by the hook script. Human-readable log messages continue to go to stderr.

## Verification

1. `ck init` in a git repo sets `core.hooksPath` to `.githooks`.
2. `ck init` outside a git repo exits 1 with error message.
3. `ck materialize --all` prints paths of files it wrote to stdout.
4. `ck materialize --all` prints nothing if no files changed (idempotent).
5. `git commit` in a repo with the hook wired runs `ck ingest && ck materialize --all` and stages materialized files.
6. `git commit` is blocked if `ck ingest` fails (e.g., LLM server not running).
7. `git commit --no-verify` bypasses the hook.
