# S6 — Deepen Materializer: Cross-Cutting Views

## Goal

Replace the `materialize_view()` stub with real cross-cutting view rendering. Two view kinds ship: `index` (all-scope listing) and `by-topic` (entity/summary filtering by configured tag). Views land under `.context-kernel/views/` as fully-regenerated markdown — no pinned-block support.

## In scope

- `list_summaries()` and `list_entities_by_scope()` on `KnowledgeStore` protocol
- Extend `upsert()` with `scope_entities` parameter so the store persists scope→entity mapping
- `render_view()` dispatch for `index` and `by-topic` view kinds
- `materialize_view()` with `graph_commit`-based freshness skip and `list[Path]` return
- `index.md`: scope name + summary one-liner + root-relative `AGENTS.md` path
- `by-topic/<tag>.md`: case-insensitive substring match on entity name/description + summary text; grouped by scope with entity listings; scopes with matching summary but no matching entities fall back to summary text
- CLI wiring: `ck materialize --all` calls `materialize_view()` for each configured view after scope materialization
- All `_FakeStore` test classes updated with new protocol methods

## Out of scope

- `recent-changes.md` view (backlog issue created — requires timestamp/git-log integration)
- Pinned blocks in views (views are fully regenerated)
- New view kinds beyond `index` and `by-topic`

## Architectural commitments

- Views are pure functions of graph state — `graph_commit` match = skip (per THEORY.md invariant 1)
- Views use root-relative paths (agents call `Read` with these directly)
- `materialize_view()` stays separate from `materialize()` — different responsibilities, CLI orchestrates sequence
- Sentinel `source_tree_hash` in view freshness headers (views span all scopes, no single source tree)
- No pinned blocks — views are fully derived cross-cutting aggregations

## Concrete specs

### KnowledgeStore protocol additions

```python
def list_summaries(self) -> list[Summary]: ...
def list_entities_by_scope(self) -> dict[ScopePath, list[Entity]]: ...
```

`upsert()` gains `scope_entities: dict[ScopePath, list[Entity]] | None = None`.

### View rendering (`materializer/views.py`)

`render_view(spec, store) -> str` dispatches on `spec.kind`:

- **`index`**: iterates `store.list_summaries()`, renders each as `## {scope}\n{summary.markdown}\n→ {scope}/AGENTS.md`
- **`by-topic`**: reads `spec.params["tag"]`, matches case-insensitive substring against `list_entities_by_scope()` entity names/descriptions and `list_summaries()` summary text. Groups matched entities by scope. Scopes with matching summary but no matching entities render the summary text instead.

### View materialization (`materializer/__init__.py`)

`materialize_view(spec, store, tree_root, config) -> list[Path]`:

1. Compute output path: `.context-kernel/views/{spec.name}.md` for `index`, `.context-kernel/views/by-topic/{tag}.md` for `by-topic`
2. Parse existing file's freshness header; skip if `graph_commit` matches
3. Render via `render_view(spec, store)`
4. Wrap with freshness header (`graph_commit` from store, sentinel `source_tree_hash`)
5. Write via `_write_if_changed()`; return written paths

### CLI wiring (`agent_cli.py`)

In `_cmd_materialize`, after the scope loop:
```python
for spec in config.materializer.views:
    all_written.extend(materialize_view(spec, store, portfolio, config.materializer))
```

## Verification criteria

1. `render_view()` with `kind="index"` produces markdown listing all scopes with summaries and `AGENTS.md` paths
2. `render_view()` with `kind="by-topic"` and `params={"tag": "auth"}` returns only entities/scopes matching "auth"
3. `by-topic` match is case-insensitive substring on entity name + description
4. `by-topic` includes scopes where only the summary (not an entity) matches the tag
5. `by-topic` groups entities by scope with entity kind and description
6. `materialize_view()` writes to `.context-kernel/views/index.md`
7. `materialize_view()` writes to `.context-kernel/views/by-topic/{tag}.md`
8. `materialize_view()` skips write when `graph_commit` matches existing header
9. `materialize_view()` returns `list[Path]` of written files
10. View files contain a freshness header with sentinel `source_tree_hash`
11. `list_summaries()` returns all summaries from the store
12. `list_entities_by_scope()` returns the scope→entity mapping
13. `upsert()` accepts and persists `scope_entities`
14. `ck materialize --all` renders views after scopes (CLI wiring)
15. All existing tests still pass
