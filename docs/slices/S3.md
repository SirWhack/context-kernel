# S3 — Deepen Ingester: Python AST handler + ingest orchestration

**Status:** spec complete, ready to build.
**[PLAN.md](../../PLAN.md) reference:** §S3.
**Authors of this spec:** decisions from `/grill-with-docs` session on 2026-05-24.

## Goal

A `PythonHandler` that extracts module, class, and function entities from Python source using `ast`, with Ousterhout-informed structured descriptions (Interface/Internals/Depth sections). A working `ingest()` body that orchestrates the full pipeline: file discovery → handler dispatch → entity extraction → ID derivation → scope summary → graph upsert.

## In scope

- `PythonHandler` implementing `StructuredHandler` protocol
- `StructuredHandler` protocol (new) for handlers that produce entities directly
- Rename `SourceHandler` → `ChunkHandler` for handlers that produce text chunks
- `RawEntity` / `RawRelationship` intermediate types for handler output
- `ingest()` orchestration body: handler registry, entity ID derivation, scope summary generation, graph upsert
- Deterministic entity IDs derived from `hash(name, kind, source_file)`
- Mechanical scope summaries generated from collected entities
- Stub `Summarizer` for the `ChunkHandler` path (real LLM Summarizer deferred)

## Concrete specs

### Two handler protocols

```python
class ChunkHandler(Protocol):
    """Produce text chunks for the Summarizer (markdown, prose, PDFs)."""
    def supports(self, path: Path) -> bool: ...
    def chunks(self, path: Path) -> list[str]: ...

class StructuredHandler(Protocol):
    """Extract entities directly from structured source (Python, TS/JS)."""
    def supports(self, path: Path) -> bool: ...
    def extract(self, path: Path) -> tuple[list[RawEntity], list[RawRelationship]]: ...
```

`MarkdownHandler` implements `ChunkHandler` (protocol rename from `SourceHandler`; class name unchanged).
`PythonHandler` implements `StructuredHandler`.

### Intermediate types

```python
@dataclass(frozen=True)
class RawEntity:
    name: str
    kind: str       # "module", "class", "function"
    description: str

@dataclass(frozen=True)
class RawRelationship:
    source_name: str
    target_name: str
    kind: str        # "inherits", "imports"
    description: str
```

Live in `context_kernel/ingester/handlers.py`. The ingest loop converts them to `Entity`/`Relationship` by deriving IDs.

### PythonHandler

Supports `.py` files. Uses `ast.parse()` to extract three entity kinds:

**`module`** — file-level preamble. One per file.

```
Module: context_kernel/ingester/handlers.py
  Docstring: "Source-format handlers..."

  Exports:
    SourceHandler (Protocol)
    MarkdownHandler (class)

  Private:
    _CHUNK_SIZE, _CHUNK_OVERLAP

  Imports:
    pathlib.Path, typing.Protocol

  Depth: 2 exports, 2 private constants, 42 LOC
```

**`class`** — each `ast.ClassDef`, including all methods as a single unit.

```
Class: MarkdownHandler
  File: context_kernel/ingester/handlers.py

  Interface:
    supports(self, path: Path) -> bool
    chunks(self, path: Path) -> list[str]

  Internals: (none)

  Depth: 2 public methods, 0 private methods, 22 LOC
  Bases: —
```

**`function`** — each top-level `ast.FunctionDef`/`ast.AsyncFunctionDef`.

```
Function: standalone_helper(x: int) -> str
  File: context_kernel/ingester/handlers.py
  Visibility: public
  Depth: 15 LOC
```

**Rules:**
- Signatures use `ast.unparse()` on annotation nodes — no resolution, no normalization.
- `_`-prefixed names are Internals; others are Interface.
- Protocol/ABC detection by inheritance only (base classes contain `Protocol` or `ABC`).
- Methods inside classes do NOT get their own entity — grouped with the class.
- Constants fold into the module preamble (listed under Exports or Private by naming convention).
- Files with syntax errors are skipped with a logged warning, not a crash.
- Empty files produce no entities.

**Relationships extracted:**
- `inherits`: class → base class name (from `ast.ClassDef.bases`)
- `imports`: module → imported name (from `ast.Import`/`ast.ImportFrom`)

### Entity ID derivation

In the ingest loop, after handlers return `RawEntity`/`RawRelationship`:

```python
entity_id = sha256(f"{name}:{kind}:{source_file_relative_path}".encode()).hexdigest()
```

`RawRelationship.source_name`/`target_name` are resolved to entity IDs by name lookup within the current file's entity set. Unresolvable names (imported types from other files) use the same hash scheme with the import's qualified path as the source file component.

### Handler registry

```python
_STRUCTURED: list[StructuredHandler] = [PythonHandler()]
_CHUNK: list[ChunkHandler] = [MarkdownHandler()]
```

Ingest loop checks `_STRUCTURED` first, then `_CHUNK`, calling `supports()`. First match wins. Files that no handler supports are skipped silently.

### `ingest()` orchestration body

```python
def ingest(
    store: KnowledgeStore,
    sources_root: Path,
    blob_root: Path,
    config: "IngesterConfig",
    *,
    summarizer: Summarizer | None = None,
    embedder: Embedder | None = None,
) -> GraphCommit:
```

Summarizer/Embedder are optional kwargs — when `None`, `ChunkHandler` sources are skipped with a log warning. This lets S3 run with `StructuredHandler` sources only; real Summarizer/Embedder wired in later.

**Steps:**
1. `walk_source_files(sources_root)` → all source files
2. For each file, find handler (`StructuredHandler` or `ChunkHandler`)
3. If `StructuredHandler`: `extract(path)` → `RawEntity`/`RawRelationship` → derive IDs → collect
4. If `ChunkHandler` and `summarizer` is not None: `chunks(path)` → `summarizer.summarize()` per chunk → derive IDs → optionally `embedder.embed()` per chunk → collect
5. If `ChunkHandler` and `summarizer` is None: skip file, log warning
6. Group collected entities by scope (parent directory relative to tree root)
7. Per scope: generate mechanical summary from collected entities
8. Compute `GraphCommit` as hash of all entity IDs + relationship data
9. `store.upsert(graph_commit, all_entities, all_relationships, all_summaries)`
10. Return `GraphCommit`

### Mechanical scope summary

Generated from collected entities per scope. Template-driven, not LLM:

```
Scope context_kernel/ingester/: 4 modules, 3 classes (1 Protocol), 5 functions.
Key interfaces: SourceHandler, StructuredHandler. Dependencies: pathlib, typing, ast.
```

Stored via `blobs.write_summary()`. Included in the `Summary` list passed to `store.upsert()`.

## Verification

1. `PythonHandler.supports()` returns `True` for `.py`, `False` for `.md`.
2. `PythonHandler.extract()` on a file with a class produces `module` + `class` entities.
3. `PythonHandler.extract()` on a file with top-level functions produces `function` entities.
4. Class entity descriptions include Interface/Internals split — public methods in Interface, `_`-prefixed in Internals.
5. Class entity descriptions include depth metrics (LOC, method counts).
6. Class entity descriptions include base classes when present.
7. Module preamble entity lists exports, private constants, imports.
8. Signatures use `ast.unparse()` — string annotations preserved as-is.
9. Entity IDs are deterministic: same file parsed twice → same IDs.
10. `ingest()` processes `PythonHandler` sources and upserts entities into the store.
11. `ingest()` skips `ChunkHandler` sources when no Summarizer is provided (with warning).
12. `ingest()` generates mechanical scope summaries from collected entities.
13. `ingest()` skips embedding for `StructuredHandler` sources.
14. `ingest()` calls `store.upsert()` with collected entities, relationships, summaries.
15. Files with syntax errors are skipped with a logged warning, not a crash.
16. Empty `.py` files produce no entities.
