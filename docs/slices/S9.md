# S9 — Wire cross-project ingest

**Status:** spec complete, ready to build.
**[PLAN.md](../../PLAN.md) reference:** §S9.
**Authors of this spec:** decisions from `/grill-with-docs` session on 2026-05-25.

## Goal

A portfolio root containing multiple declared projects, each ingested with per-project entity namespaces (no merging per THEORY.md non-goal 2). ConfigStore learns the portfolio shape from `[[projects]]` in `config.toml`. Backward-compatible: single-project usage without `[[projects]]` works identically to before.

## In scope

- `ProjectSpec` dataclass in `config_store.py` with `name` derived from `path.name`
- `[[projects]]` table parsing in `config_store.load()`
- Five validations at load time: relative path, non-empty name, identifier regex, no duplicate names, path exists on disk
- Default single-project when `[[projects]]` absent (no prefix, full backward compat)
- `ingest()` gains `project_name: str | None` parameter
- Entity IDs prefixed with project name: `sha256(project:name:kind:source_file)`
- ScopePaths prefixed with project name: `ScopePath(Path("project-a/src"))`
- `_cmd_ingest` loops over declared projects
- `_cmd_materialize --all` loops over declared projects, prefixes scopes

## Out of scope (deferred)

| Concern | Where |
|---|---|
| Cross-project entity merging | THEORY.md non-goal 2; future EntityResolver |
| Per-project config overrides | Future; single `IngesterConfig` for now |
| Per-project graph stores | Rejected in Q6; single shared store |
| Auto-discovery of projects | Rejected in Q1; explicit declaration only |

## Concrete specs

### ProjectSpec

```python
@dataclass(frozen=True)
class ProjectSpec:
    path: Path  # relative to portfolio_root

    @property
    def name(self) -> str:
        return self.path.name
```

Lives in `config_store.py`. `name` is derived from the last component of `path` — no separate config field.

### Config changes

`Config` gains `projects: list[ProjectSpec]`. Default when `[[projects]]` absent: `[ProjectSpec(path=Path("."))]` — single-project mode with no entity/scope prefixing.

### config.toml format

```toml
[[projects]]
path = "model-time"

[[projects]]
path = "evergreen-site"
```

### Load-time validation

1. `path` must be relative (no absolute paths).
2. `path.name` must be non-empty — rejects `Path(".")` in explicit declarations.
3. `path.name` must match `^[a-zA-Z0-9_][a-zA-Z0-9_.-]*$`.
4. No duplicate `path.name` values across projects.
5. `portfolio_root / path` must exist on disk.

All violations raise `ValueError` from `load()`.

### Entity ID namespacing

`_derive_entity_id` gains a `project` parameter:

```python
def _derive_entity_id(name: str, kind: str, source_file: str, project: str | None = None) -> str:
    if project:
        return sha256(f"{project}:{name}:{kind}:{source_file}".encode()).hexdigest()
    return sha256(f"{name}:{kind}:{source_file}".encode()).hexdigest()
```

### ScopePath namespacing

Inside `ingest()`, scope keys are prefixed when `project_name` is not None:

```python
scope_key = str(file_path.parent.relative_to(sources_root))
if project_name:
    scope_key = f"{project_name}/{scope_key}"
```

### ingest() signature change

```python
def ingest(
    store: KnowledgeStore,
    sources_root: Path,
    blob_root: Path,
    config: "IngesterConfig",
    *,
    project_name: str | None = None,
    summarizer: "Summarizer | None" = None,
    embedder: "Embedder | None" = None,
) -> GraphCommit:
```

### CLI orchestration

`_cmd_ingest` loops over `config.projects`:

```python
def _cmd_ingest(args, config) -> str:
    portfolio = args.portfolio.resolve()
    store = LightRAGStore(portfolio / ".context-kernel" / "graph")
    commit = None
    for project in config.projects:
        project_name = None if project.path == Path(".") else project.name
        commit = ingest(store, portfolio / project.path, portfolio, config.ingester, project_name=project_name)
    return str(commit)
```

`_cmd_materialize --all` mirrors the pattern:

```python
if args.all_scopes:
    for project in config.projects:
        project_root = portfolio / project.path
        project_name = None if project.path == Path(".") else project.name
        for scope in discover_scopes(project_root):
            full_scope = ScopePath(Path(project.name) / scope) if project_name else scope
            all_written.extend(materialize(full_scope, store, portfolio, config.materializer))
    for spec in config.materializer.views:
        all_written.extend(materialize_view(spec, store, portfolio, config.materializer))
```

### GraphCommit behavior

Per-project `GraphCommit` — each `ingest()` call produces its own commit from the entities it upserted. The journal logs the final commit from the loop. FreshnessGate compares per-scope, so project-prefixed scopes match correctly.

## Verification

1. `[[projects]]` parsed into `list[ProjectSpec]` with names derived from path.
2. Missing `[[projects]]` defaults to single project with `path=Path(".")`.
3. Invalid project name (slashes, whitespace) raises `ValueError` at load time.
4. Duplicate project names raise `ValueError` at load time.
5. Non-existent project path raises `ValueError` at load time.
6. `ingest()` with `project_name="proj-a"` produces project-prefixed ScopePaths.
7. `ingest()` with `project_name="proj-a"` produces different entity IDs than `project_name=None`.
8. `ingest()` with `project_name=None` produces identical entity IDs and scopes to pre-S9 behavior.
9. Two `ingest()` calls with different `project_name` values against the same store don't collide.
10. `_cmd_ingest` with two declared projects ingests both into the same store.
11. `_cmd_materialize --all` with two declared projects discovers scopes from both.
12. All pre-existing tests pass without modification (backward compat).
