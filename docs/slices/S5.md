# S5 — Deepen OrientationServer `find`

**Status:** spec complete, ready to build.
**[PLAN.md](../../PLAN.md) reference:** §S5.
**Authors of this spec:** decisions from `/grill-with-docs` session on 2026-05-25.

## Goal

Replace the `find` stub with real embedding-similarity retrieval over a hybrid corpus of entity descriptions and per-scope summaries. Wire the MCP stdio server (`serve()`) so agents can call both `overview` and `find` via the MCP protocol. Implement the `Embedder` (httpx to llama-server) so embeddings are computed at ingest time and queries are embedded at `find` time.

## In scope

- `HttpEmbedder` implementation — httpx POST to llama-server on port 8081
- Asymmetric prompting via `mode` parameter on `Embedder` protocol (`"passage"` for ingest, `"query"` for find)
- Embed entity descriptions and scope summaries at ingest time (modify `ingest()`)
- `SearchResult` dataclass and `EmbeddedChunk` storage type in the graph protocol
- `KnowledgeStore.search_similar()` protocol method — delegates to NanoVectorDB
- `similarity.nearest_chunks()` — wired through the protocol
- `find()` tool — real embedding-similarity search with optional scope filter, token budget enforcement
- `serve()` MCP stdio server via official `mcp` Python SDK (FastMCP)
- MCP tool registration for `overview` and `find`
- Tests against real llama-server embedder (auto-launch fixture)

## Out of scope (deferred)

| Concern | Where |
|---|---|
| LLM-generated per-scope summaries (Summarizer impl) | S1 Phase 2. `find` automatically benefits when richer summaries land — they'll be embedded and searchable |
| `LightRAGStore` adapter (real NanoVectorDB backend) | S1 Phase 2. S5 implements against the `KnowledgeStore` protocol; tests use a `_FakeStore` with brute-force cosine for the vector search path |
| Cross-project entity merging | EntityResolver (ARCHITECTURE.md §6) |
| HTTP MCP transport | Deferred per ARCHITECTURE.md §6 |
| Keyword/substring fallback when embedder unavailable | Not implemented; clean error message instead |

## Concrete specs

### Embedder protocol change

```python
class Embedder(Protocol):
    def embed(self, text: str, *, mode: Literal["passage", "query"] = "passage") -> bytes: ...
```

- `mode="passage"` — plain text, used at ingest time for entity descriptions and summaries
- `mode="query"` — prefixed with `Instruct: Find relevant code modules, classes, functions, or documentation in a software portfolio.\nQuery: {text}`, used at `find` time

### HttpEmbedder implementation

- POST to `{endpoint}/embeddings` with `{"input": text, "model": model}`
- Parse response `data[0].embedding` float list
- Pack as `struct.pack(f"{dim}f", *floats)` → bytes
- Endpoint default: `http://127.0.0.1:8081/v1` (from `IngesterConfig`)

### Graph protocol additions

**`EmbeddedChunk`** — the write-path type for vector storage:
```python
@dataclass(frozen=True)
class EmbeddedChunk:
    id: str              # entity_id or summary_digest
    embedding: bytes     # raw float32 vector
    chunk_text: str      # the embedded text
    source_path: str     # file path for citation
    kind: str            # "entity" or "summary"
    scope: ScopePath     # scope for filtering
```

**`SearchResult`** — the read-path type from vector search:
```python
@dataclass(frozen=True)
class SearchResult:
    chunk_text: str
    source_path: str
    score: float
    kind: str            # "entity" or "summary"
    scope: ScopePath
```

**`KnowledgeStore.search_similar()`** — new protocol method:
```python
def search_similar(
    self, query_embedding: bytes, k: int, scope: ScopePath | None = None,
) -> list[SearchResult]: ...
```

**`KnowledgeStore.upsert()`** — extended with optional chunks parameter:
```python
def upsert(
    self, graph_commit, entities, relationships, summaries,
    chunks: list[EmbeddedChunk] | None = None,
) -> None: ...
```

### Ingest-time embedding

`ingest()` embeds both structured handler entities and scope summaries when an `Embedder` is provided:

- After entity resolution: embed each `entity.description` with `mode="passage"`
- After scope summary generation: embed each summary's markdown with `mode="passage"`
- Write embeddings to `.context-kernel/embeddings/<sha256>.bin`
- Build `EmbeddedChunk` list and pass to `store.upsert()`

### `find` tool

```python
def find(query, scope, max_tokens, tree_root, store, embedder) -> str:
```

- If `embedder` is None: return clear error message
- Embed query with `mode="query"`; catch connection errors gracefully
- Call `store.search_similar(query_embedding, k=10, scope=scope)`
- Pass results to `response.assemble()` for token-budget-capped formatting
- Default `k=10`, default `max_tokens=4096`

### `find` error handling

- Embedder unreachable: return `"Embedding service unavailable at {endpoint}. Start the embedder server and retry, or use overview for scope-level orientation."`
- No results: return `"No results found for query: \"{query}\""`
- No crash on any failure path

### MCP tool schemas

**`find`:**


```json

```

### MCP server (`serve()`)

- Uses `FastMCP` from the official `mcp` Python SDK
- Registers `overview` and `find` as tools
- stdio transport (spawned by `ck mcp`)
- `serve()` signature gains `embedder: Embedder | None = None`

- If server already running on port 8081, reuse it
- If model file or binary not found, skip embedding-dependent tests

## Verification

1. `HttpEmbedder.embed()` returns bytes of expected length (`dim * 4` bytes for float32).
2. `HttpEmbedder.embed(text, mode="query")` produces different bytes than `mode="passage"` for the same text.
3. `ingest()` with an embedder produces `EmbeddedChunk` entries for entity descriptions.
4. `ingest()` with an embedder produces `EmbeddedChunk` entries for scope summaries.
5. `ingest()` without an embedder still works (no embeddings, no crash).
6. `store.search_similar()` returns results ranked by descending score.
7. `store.search_similar()` with scope filter returns only results from that scope.
8. `find()` returns relevant results for a semantic query against ingested code.
9. `find()` respects token budget — response length stays within `max_tokens * 4` chars.
10. `find()` with no scope searches across all scopes.
11. `find()` with a scope filters results to that scope.
12. `find()` with embedder unavailable returns a clear error message, not a crash.
13. `find()` with no matching results returns a "no results" message.
14. `serve()` starts an MCP stdio server that registers `overview` and `find` tools.
15. MCP `overview` tool returns scope summaries (existing behavior preserved).
16. MCP `find` tool accepts query, optional scope, optional max_tokens.
17. Entity IDs and embeddings are deterministic — same file ingested twice produces same chunks.

## Future improvement

When S1 Phase 2 lands the `Summarizer` implementation (LLM-generated per-scope prose), `find` automatically benefits — richer scope summaries will be embedded and searchable alongside entity descriptions. No changes to S5 code needed.
