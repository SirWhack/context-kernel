## Goal

Run the full Context Kernel pipeline against a two-project portfolio on the 7900 XTX and verify that cross-project orientation, pre-commit freshness, and sub-60s latency all work end-to-end. This is the v1 release gate — no new code, just a manual dogfood demo with pass/fail checkpoints.

- Full `ck ingest && ck materialize --all` run across both projects
- MCP `find` query returning cross-project results

- Journal-based latency verification

## Concrete specs

### Portfolio setup

1. Choose a portfolio root (e.g., `~/Code/`) containing ≥2 projects:
   - ≥1 Python project (e.g., `model-time`)
   - ≥1 TS/JS project with ≥50 source files

2. Create `.context-kernel/config.toml` at the portfolio root with at minimum:

```toml
[[projects]]
path = "model-time"

[[projects]]
path = "other-project"

[[materializer.views]]
name = "index"
kind = "index"
```

Required sections:
- `[[projects]]` — ≥2 entries with relative paths to project directories
- `[[materializer.views]]` — at least an `index` view

All other settings (ingester model, embedder, storage backend) use defaults.

### Demo runbook

1. **Ingest:** Run `ck ingest --portfolio <portfolio-root>`. Verify clean exit (exit code 0).
2. **Materialize:** Run `ck materialize --all`. Verify `AGENTS.md` + `CLAUDE.md` bridge files appear under both project trees. Verify cross-cutting views render under `.context-kernel/views/`.
3. **MCP find:** Start `ck mcp`. Issue a `find` query whose answer spans both projects. Verify the response includes file-path citations from ≥2 distinct project-name prefixes.
4. **Freshness proof:** Edit a source file in one project. Run `git commit`. Verify the pre-commit hook fires (`ck ingest && ck materialize --all`), the materialized files for the edited scope update, and changed files are staged.
5. **Latency check:** Inspect `.context-kernel/log.md`. Each per-project `ck ingest` invocation must show `duration_ms` < 60000.

## Verification

1. `config.toml` at portfolio root has `[[projects]]` with ≥2 entries and `[[materializer.views]]` with at least `index`.
2. `ck ingest` completes without error for all declared projects.
3. `ck materialize --all` writes `AGENTS.md` + `CLAUDE.md` bridge files under both project trees.
4. Cross-cutting views (`index.md`, any `by-topic` views) render under `.context-kernel/views/`.
5. `ck mcp` starts; a `find` query returns results citing scopes from ≥2 distinct project-name prefixes.
6. Edit a source file in one project → `git commit` → pre-commit hook fires → materialized files for that scope update and are staged.
7. Each per-project `ck ingest` invocation in `.context-kernel/log.md` shows `duration_ms` < 60000.
