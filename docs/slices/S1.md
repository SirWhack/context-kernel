# S1 — Walking skeleton: ingest → materialize → check → mcp

**Status:** architecturally complete. Phase-1 implementation (no LightRAG) ready to start. Phase-2 implementation (LightRAG-dependent) and E2E verification gated on [S0](./S0.md).
**[PLAN.md](../../PLAN.md) reference:** §S1 — the tracer-bullet slice.
**Authors of this spec:** decisions from `/grill-with-docs` session on 2026-05-24.

## Goal

End-to-end pipeline (`ck ingest && ck materialize && ck check && ck mcp`) against one small markdown-only project (~50 files — inherited from S0's chosen corpus). Every module gets a body. The exit signal is a recorded **first-read latency** number against a stale ~50-file scope on the 7900 XTX — under 60s passes; over 60s stops and returns to `/grill-architecture` because [ADR-0003](../adr/0003-pull-based-jit-regeneration.md) is wrong.

## Concrete specs locked in 2026-05-24

### `AGENTS.md` file content shape

```markdown
<!-- context-kernel-freshness
graph: 7f3a4b2c...
source-tree: 2c4e8a1f...
materialized: 2026-05-24T15:30:00Z
-->

The auth module owns session token issuance and verification for the API. The
canonical entry point is `verify_session_token` (auth/session.py); it consults
the redis-backed `SessionStore` (auth/store.py) and falls back to `Customer.id`
lookup via the billing module when a token has no recorded session...
```

**Rules:**
- HTML comment block at top with sentinel `context-kernel-freshness` (greppable across the portfolio for "all materialized files").
- Three header fields, `key: value` form, one per line.
- Blank line, then the `Summary.markdown` body verbatim from the Graph.
- No other sections: no file list, no entity index, no headings except those the synthesis prompt chose to emit. Per [ADR-0006](../adr/0006-files-as-primary-interface.md), `AGENTS.md` points; files deliver.

### `CLAUDE.md` bridge file content (per scope)

```markdown
@AGENTS.md
```

One line. No header. The bridge has no content to be stale about — it points; `AGENTS.md` delivers. Per [ADR-0002](../adr/0002-materialize-agents-md-with-claude-code-bridge.md).

### Synthesis prompt (Ingester second-pass call)

```
You are documenting a directory in a software portfolio for a coding agent
that has never seen this codebase. The agent needs orientation — what's in
this scope, what's important, and how it relates to the rest of the
portfolio — to know where to look first.

Scope: {scope_path}

Files in scope:
{file_list_with_previews}

Entities extracted from this scope:
{entities}

Relationships within this scope:
{within_scope_relationships}

Relationships crossing to other scopes:
{cross_scope_relationships}

Write a ~{target_tokens}-token markdown orientation. Name canonical file
paths in prose so the reader can Read them directly. Do not list files. Do
not list entities. Write prose.
```

**Inputs:**
- `scope_path` — directory path relative to portfolio root (e.g. `src/auth/`).
- `file_list_with_previews` — for each file in scope: `<relpath>: <first heading or first paragraph>`. NOT full file content — that is what makes this a synthesis over LightRAG's output, not a re-read of every source.
- `entities` — name, kind, description from LightRAG, filtered to entities whose chunks came from files in this scope.
- `within_scope_relationships` — entities in this scope linked to each other.
- `cross_scope_relationships` — entities in this scope linked to entities elsewhere. Derived per [ADR-0009](../adr/0009-cross-scope-relationships-via-source-id.md) source_id traversal.
- `target_tokens` — from `ConfigStore.IngesterConfig.summary_target_tokens`; default 500.

**Output shape:**
- Free-form markdown prose, no required headings.
- Names canonical file paths inline so the agent can `Read` them.
- Approximate target length — exact compliance not required.

### `ck` subcommand semantics

| Command | Inputs | Side effects | Returns |
|---|---|---|---|
| `ck ingest [--portfolio ROOT]` | Optional `--portfolio` override (defaults to CWD) | Runs LightRAG ingest + per-scope second-pass synthesis over all source files in portfolio | exit 0 on success; non-zero with `IngestionError` on failure |
| `ck materialize [--scope PATH \| --all]` | Optional scope path or `--all` flag | Renders `AGENTS.md` + `CLAUDE.md` bridge for one scope or all | exit 0 on success; non-zero with `MaterializationError` on failure |
| `ck check PATH` | Path to a materialized file | Ensures file at PATH on disk is fresh — triggers ingest+materialize if its freshness header does not match current state | exit 0 if fresh (no-op or re-materialized); non-zero with `StaleReadError` if regen itself failed |
| `ck mcp` | None | Starts the stdio MCP server, exposes `overview` + (stubbed) `find` tools, runs until stdin closes | exit 0 on graceful shutdown |

### Freshness logic in `ck check` / `FreshnessGate.check`

1. Parse header from PATH; extract `graph_commit_header` and `source_tree_hash_header`.
2. Compute `source_tree_hash_current` over the scope's source files (the scope is inferred from PATH).
3. Compute `graph_commit_current` from the Graph (cached at end of last ingest).
4. **Both match:** file is fresh. Return.
5. **Only `graph_commit` differs:** invoke `Materializer.materialize(scope)`. Return.
6. **`source_tree_hash` differs:** invoke `Ingester.ingest(...)`, then `Materializer.materialize(scope)`. Return.
7. **Any step fails:** raise `StaleReadError`; propagate up.

### Scope discovery rules (during ingest)

A **scope** is any directory under `portfolio_root` containing ≥1 ingested file.

Exclusions (hardcoded for S1; configurable in a later slice):
- `.git/`
- `.context-kernel/` (the kernel's own state — avoiding a feedback loop)
- `node_modules/`
- `__pycache__/`
- Any directory name starting with `.` (other than `portfolio_root` itself)

Empty directories are not scopes; directories whose only files are excluded by handler type (e.g. all-Python in S1) are also not scopes (no ingested files).

### `OperationalJournal` line format (S1 minimum-viable)

One markdown table row per invocation, appended to `.context-kernel/log.md`:

```markdown
| 2026-05-24T15:30:00Z | abc-def-... | ingest      | --portfolio .       | 12345ms | 0 |
| 2026-05-24T15:31:02Z | def-abc-... | materialize | --scope src/auth/   |    87ms | 0 |
| 2026-05-24T15:32:14Z | xyz-...     | check       | docs/AGENTS.md      |    23ms | 1 |
```

Columns: timestamp, invocation UUID, command, args, duration, exit code. Regen chains (a `check` that triggered ingest+materialize) get an additional row referencing the parent UUID. Full schema lives in [ARCHITECTURE.md](../../ARCHITECTURE.md) §3.2. S1 logs only the basics; richer journal entry per S8.

### Two further implementation decisions

- **Drop synthesis caching for S1.** [ADR-0007](../adr/0007-per-scope-summaries-at-ingest.md) notes that summaries are *cacheable* by scope-contents hash, but the cache key has subtle dependencies (a scope whose own source files did not change may still have stale cross-scope dependencies — different cache key). For S1's ~10-scope demo corpus, re-summarize all scopes on every ingest. Affordable. Optimize later if measurement shows it matters.
- **`overview(scope, max_tokens)` returns the `Summary` body, stripped of the freshness header**, truncated to `max_tokens` at the nearest paragraph boundary. The header is operational metadata; agents don't need it.

## Verification

### Phase 1 (unit tests, no E2E)

Each phase-1 module fills the corresponding `tests/test_*.py` TODO(test) marker. Targets to test against the locked specs above:

- `headers.render` ↔ `headers.parse` round-trip on a known fixture.
- `pinned.extract` then `pinned.merge` is a no-op on input without `<!-- pinned -->` blocks.
- `change_detection.changed_since` returns `[]` for an unchanged tree.
- Scope discovery against a fixture tree exercises every exclusion rule.
- `assemble` truncates at the nearest paragraph boundary, not mid-sentence.
- `agent_cli.main(["ingest", "--portfolio", "..."])` dispatches to the Ingester stub.

### Phase 2 (E2E, gated on [S0](./S0.md))

Run the full pipeline against S0's corpus (~50 markdown files) on the 7900 XTX:

1. `ck ingest` succeeds; produces a `graph_commit` and per-scope `Summary` records.
2. `ck materialize --all` produces `AGENTS.md` + `CLAUDE.md` at every discovered scope.
3. `ck check` on a fresh file returns exit 0 with no regen.
4. Edit one source file; `ck check` on a materialized file in that file's scope triggers ingest+materialize and returns exit 0 with fresh content on disk.
5. `ck mcp` starts; `overview(scope)` via MCP returns the `Summary` body without the freshness header, capped to max_tokens.
6. **First-read latency proxy:** wall-time from `ck check` invocation to fresh-on-disk on a cold scope < 60s. Threshold from [ARCHITECTURE.md](../../ARCHITECTURE.md) §7 and [THEORY.md](../../THEORY.md) open question 3.
7. **Cross-scope density** (measured during S0; re-confirmed on the materialized graph): ≥15% per [ADR-0009](../adr/0009-cross-scope-relationships-via-source-id.md) thresholds.

If (6) or (7) fails, S1 stops and returns to the relevant grill skill per the threshold rules.

## Open implementation questions (deferred to first phase-2 PR)

- **`LightRAGStore` wrapping level.** Wrap LightRAG's high-level `LightRAG` class or instantiate the storage trio directly? S0 will show which is cleaner.
- **Markdown chunking.** LightRAG's built-in chunker or a basic char-window splitter? Probably the built-in; defer until phase 2.
- **Where does the cached `graph_commit_current` live for `FreshnessGate.check`?** On disk at `.context-kernel/graph_commit` (last-ingest), or recomputed from sources on every check? The latter is correct but more expensive; the former is fine if the Ingester writes it as the last step of every successful ingest.
