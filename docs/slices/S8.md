# S8 — Harden Observability + OperationalJournal

## Goal

Unify the codebase's ad-hoc logging (mix of `print(stderr)` and `logging.getLogger`) into a single structured logging layer. Add a `context_kernel/logging.py` module with JSON/human-readable formatters controlled by `CK_LOG_FORMAT`. Propagate invocation UUID via `contextvars` so every log line is traceable. Add domain-specific log events: FreshnessGate hit/miss, Materializer regen timing, Ingester summary. Enrich `JournalEntry` with `graph_commit`; remove unused `regen_chain`.

## In scope

- New `context_kernel/logging.py` module: `configure()` function, custom `Formatter` (JSON/human), `contextvars` for invocation UUID
- `CK_LOG_FORMAT` env var: `human` (default) or `json`
- `CK_LOG_LEVEL` env var: maps to stdlib levels, default `INFO`
- Flat log line envelope: `ts`, `level`, `invocation`, `module`, `msg` + arbitrary extras
- FreshnessGate: log hit (scope, graph_commit) and miss (scope, stale vs current graph_commit, source_tree staleness)
- Materializer: log on completion (scope, graph_commit, duration_ms, files_written); same for views
- Ingester: log summary on completion (files_processed, entities, relationships, graph_commit, duration_ms)
- `JournalEntry`: add `graph_commit: str | None`, remove `regen_chain`
- Journal markdown table: add `graph_commit` column (8-char truncated), drop `regen_chain` column
- `agent_cli.main()`: call `configure()` at startup, set invocation UUID contextvar
- Replace all `print(..., file=sys.stderr)` with structured log calls in materializer and agent_cli
- Tests for logging module, updated journal tests, integration tests for log output

## Out of scope

- Per-module log level overrides (`CK_LOG_LEVEL_INGESTER=DEBUG` etc.)
- Metrics collection (Prometheus, OTel)
- Automatic log rotation
- Quiet mode (use `CK_LOG_LEVEL=ERROR` instead)
- Regen chain tracking in journal (reconstructable from structured logs via UUID)

## Architectural commitments

- Log format is a Parnas-secret hidden behind `context_kernel/logging.py`
- Invocation UUID is ambient context via `contextvars`, not a function parameter
- Each module logs what it owns: FreshnessGate logs decisions, Materializer logs regen, Ingester logs extraction
- Journal is a persistent ledger (markdown table); structured logs are ephemeral trace (stderr)
- Log volume bounded per invariant 4 — content-address hashes only, never file contents

JSON format (one line): `{"ts": "2026-05-25T14:30:00Z", "level": "INFO", "invocation": "uuid", "module": "context_kernel.ingester", "msg": "ingested", "files_processed": 50}`

Human format: `2026-05-25T14:30:00Z [INFO] ingester: ingested files_processed=50 entities=120 (invocation=abc12345)`

### JournalEntry changes

```python
@dataclass(frozen=True)
class JournalEntry:
    invocation_id: UUID
    started_at: datetime
    command: str
    args: list[str]
    duration_ms: int
    exit_code: int
    graph_commit: str | None  # added
    # regen_chain: removed
```

### Journal table format

```
| timestamp | invocation | command | args | duration_ms | exit | graph_commit |
```

`graph_commit` truncated to first 8 characters for readability; `None` renders as `-`.

### FreshnessGate log events

- Hit: `log.info("freshness hit", extra={"scope": scope, "graph_commit": gc})`
- Miss: `log.info("freshness miss", extra={"scope": scope, "stale_graph_commit": old_gc, "current_graph_commit": gc, "source_tree_stale": bool})`

### Materializer log events

- `log.info("materialized", extra={"scope": scope, "graph_commit": gc, "duration_ms": elapsed, "files_written": N})`
- `log.info("materialized_view", extra={"view": name, "kind": kind, "graph_commit": gc, "duration_ms": elapsed})`

### Ingester log events

- `log.info("ingested", extra={"files_processed": N, "entities": N, "relationships": N, "graph_commit": commit, "duration_ms": elapsed})`
