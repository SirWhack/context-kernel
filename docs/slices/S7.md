# S7 — Harden Materializer: Pinned-Block Merge

## Goal

Harden the `<!-- pinned -->` block system so human-curated context is treated as first-class data. Add optional labels, whitespace normalization, label-based deduplication, malformed-block warnings, and full round-trip integration tests. Pinned blocks are the highest-quality data in the system — deliberately authored human context.

## In scope

- `PinnedBlock(label: str | None, content: str)` dataclass in `pinned.py`
- Optional label syntax: `<!-- pinned:label-name -->`
- `extract()` returns `tuple[list[PinnedBlock], list[str]]` (blocks + warnings)
- Whitespace normalization: strip leading/trailing blank lines on extract, consistent padding on merge
- Label-based deduplication: duplicate labels → last wins + warning
- Malformed block detection: unpaired `<!-- pinned -->` tags → warning (content still lost)
- `merge()` accepts `list[PinnedBlock]`, renders with labels preserved
- Update `materialize()` to use new signatures
- Integration tests: pinned blocks survive regeneration cycles

## Out of scope

- Positional anchoring (backlog: `PVTI_lAHOAcFFQc4BYnivzgtwZd4`)
- Prompt-level integration with Summarizer (backlog: `PVTI_lAHOAcFFQc4BYnivzgtwaDU`)
- Pinned blocks in cross-cutting views (views are pure projections, no side inputs)
- `ck pin` / `ck unpin` CLI commands
- Nested pinned blocks (forbidden; warned)

## Architectural commitments

- Pinned blocks are human-curated data rendered as markdown but tracked as structured data (per CONTEXT.md)
- `AGENTS.md` only — views have no pinned block support (per S6 decision)
- Labels provide identity for dedup; unlabeled blocks are never deduped
- Warnings are returned as data from `extract()`, not logged — caller decides how to surface
- `PinnedBlock` lives in `pinned.py` (local to materializer, not a cross-module type)

Regex: `<!-- pinned(?::(\w[\w-]*))? -->\n(.*?)<!-- /pinned -->`

Warnings emitted for:
- Unpaired `<!-- pinned -->` (opening without closing)
- `<!-- pinned -->` inside an already-matched block (nesting attempt)
- Duplicate labels (keeps last, warns about earlier)

Whitespace: strip leading/trailing blank lines from captured content.

Renders each block as:


Consistent single blank line between blocks.

### materialize() update

Update the call site in `materializer/__init__.py` to unpack the new return type and pass warnings through (log to stderr for now).

## Verification criteria

1. `PinnedBlock` dataclass with `label` and `content` fields
2. `extract()` returns `tuple[list[PinnedBlock], list[str]]`
3. Unlabeled `<!-- pinned -->` blocks extracted with `label=None`
4. Labeled `<!-- pinned:foo -->` blocks extracted with `label="foo"`
5. Content whitespace normalized: leading/trailing blank lines stripped
6. Unpaired opening tag produces a warning string
7. Duplicate labels: last wins, warning emitted for earlier
8. `merge()` renders blocks with labels preserved in tags
9. `merge()` with empty list is identity
10. Full round-trip: materialize → hand-edit pinned block → re-materialize → block survives
11. Multiple labeled blocks survive regeneration and maintain order
12. Pinned blocks survive when `graph_commit` changes (new summary, blocks persist)
13. `materialize()` surfaces warnings from `extract()`
14. All existing tests still pass
