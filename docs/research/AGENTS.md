This scope defines the research and design foundation for **Context Kernel**, a hosted knowledge-graph system that maintains a "living model" of a codebase's purpose, module contracts, design decisions, and invariants. Its core differentiator is answering *"what does this codebase believe, and did this change preserve that theory?"* rather than simply locating code. The system is built on a graph-based retrieval architecture derived from LightRAG, which achieves comparable accuracy to GraphRAG with 10x token reduction and 65-80% cost savings for large corpora. The ingestion pipeline, triggered by GitHub App webhooks on every push, performs LLM entity extraction via a Summarizer, generates embeddings via the Embedder, and stores results in a graph store backed by Cloud SQL with pgvector.

The key interfaces include a **hosted MCP server** using Streamable HTTP and OAuth 2.1, providing per-tenant authenticated endpoints for coding agents to query the knowledge graph. The GitHub App acts as a read-only integration that observes repository state without write permissions, while GitHub OAuth serves as the upstream identity provider. The MCP server exposes tools for querying architectural theory violations, ADR constraints, affected invariants, and required context before editing code. The highest-value intervention is proactive: agents read theory before writing code, preventing drift entirely, rather than reactive drift detection after code is written.

Internally, the system follows a modular architecture with a pluggable **KnowledgeStore protocol** abstracting the graph backend. The embedding module has resolved on **Qwen3-Embedding-0.6B** as the primary model, served via sentence-transformers on PyTorch ROCm, chosen for its MTEB English Retrieval score of 61.83, 32K context window, asymmetric instruction-aware retrieval, and Apache-2.0 license. This model co-resides on a single AMD 7900 XTX GPU with 24 GB VRAM alongside a 17-20 GB quantized MoE LLM, leaving limited headroom. The ingestion pipeline uses LangChain's recursive splitters that keep heading context attached to child chunks, and LlamaIndex's labeled property graph index for building typed nodes and typed edges.

Key dependencies include **LightRAG** as the graph backend, **Cloud SQL with pgvector** for storage, **Modal** for scale-to-zero GPU inference, **Neon** for database and auth services, and **McpAgent** for MCP server hosting. The system integrates with GitHub's webhook API (10-second response requirement, no automatic retries) and respects rate limits of 5,000 requests/hour per installation. Several architectural decisions remain deferred until after v1 dogfooding, including whether to build a GitHub Action or jump straight to the GitHub App, the hosting platform choice (Cloudflare vs. GCP vs. hybrid), and the pricing model and go-to-market strategy.
