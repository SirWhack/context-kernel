This scope runs a head-to-head A/B evaluation harness that measures whether the Context Kernel MCP helps a coding agent ground itself in an unfamiliar repository faster and more cheaply than a plain grep baseline. The harness orchestrates two headless Claude Code (sonnet) sessions — a kernel arm that uses only `mcp__ck__find`, `mcp__ck__overview`, and `Read` tools over a per-repo stdio `ck mcp` server, and a grep arm restricted to `Grep`, `Glob`, `Read`, and `Bash` over the raw filesystem. Both arms answer the same numbered battery of curated questions, and the resulting transcripts are scored by `h2_eval.py` across five dimensions: COST, HALLUCINATION, RECALL, GROUNDED, and ASPECT-PRECISION (the last only when the repo carries an `ontology.toml`).

The public API surface centers on `run_eval.py`, which exports `load_env`, `load_tasks`, `build_prompt`, `write_gold`, `write_rubric`, `run_arm`, `score`, and `main`. The `main()` function parses `--repo`, `--arm`, `--no-score`, and `--score-only` flags, then delegates to `run_arm()` for each requested arm. `run_arm()` spawns a subprocess with `--strict-mcp-config` pointing to the repo's local graph, prepends a synthetic user turn for robust arm detection, and captures stream-json output to `evals/runs/sessions/<repo>/battery-<arm>.jsonl`. After both arms complete, `score()` invokes `h2_eval.py` to produce the comparison. The harness enforces tool isolation via `--disallowedTools` (not `--allowedTools`, which under `bypassPermissions` only pre-approves but does not block), and uses a comprehensive `ESCAPE` list to prevent the grep arm from accessing kernel tools like `Workflow` or `Agent`.

Internally, the harness relies on a few key design decisions. Each session runs in a neutral temporary working directory with no `CLAUDE.md` auto-load and `--add-dir <repo>` to isolate the retrieval method. The prompt rule requires "cite a file only if you opened it this session" to defend against memorization from training data. The `write_gold()` function emits a `gold.toml` recall oracle from the task file, while `write_rubric()` emits key-fact rubrics for knowledge rounds (location rounds skip this). The `GROUNDED` axis in `h2_eval` checks that gold files were actually `Read` (not merely named), providing a defense against hallucinated citations — when `GROUNDED == RECALL`, no file was cited from memory.

Dependencies are minimal: the harness imports only from `argparse`, `json`, `os`, `subprocess`, `sys`, `tempfile`, and `pathlib`. It shells out to `claude` for the headless sessions and to `scripts/h2_eval.py` for scoring. Session transcripts are gitignored because they contain corpus content, while the runner, task files, and README are committed. The task files themselves are curated per-repository question batteries with hand-verified gold file lists covering diverse file types (code, infra/config).
